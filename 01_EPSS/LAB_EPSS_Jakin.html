Objective¶

The primary objective of this laboratory report is to analyze and interpret vulnerability data using the Exploit Prediction Scoring System (EPSS). base_url = "https://services.nvd.nist.gov/rest/json/cves/2.0"
date_start_NVD = '2025-09-01T00:00:00.000Z' # Do NOT change these dates
date_end_NVD   = '2025-10-01T00:00:00.000Z' # Do NOT change these dates
start_index = 0
results_per_page = 1000
total_results = 1 

all_cves = []

while start_index < total_results:
    params = {
        "pubStartDate": date_start_NVD,
        "pubEndDate": date_end_NVD,
        "resultsPerPage": results_per_page,
        "startIndex": start_index,
        "noRejected": ""
    }
    response = requests.get(base_url, params=params, timeout=6)
    if response.status_code != 200:
        print("Error:", response.status_code)
        break

    data = response.json()
    total_results = data.get("totalResults", 0)

    all_cves.extend(data.get("vulnerabilities", []))

    start_index += results_per_page
    print(start_index)

def cvss_categorization(score):
    if pd.isna(score):
        return 'Unknown/NA'
    elif score < 4.0:
        return 'Low'
    elif 4.0 <= score < 7.0:
        return 'Medium'
    elif 7.0 <= score < 9.0:
        return 'High'
    else:
        return 'Critical'

Additional analysis¶

The idea is to explore which features of the dataset might help me predict changes in the EPSS score, from low to high.

EPSS is influenced by both technical severity (CVSS) and threat context, for example exploit availability, attention from researchers, public references and many more.

Most relevant predictors:¶

  • Reference-related features:

    • num_references

      A CVE with many references (especially GitHub or exploit DBs) is more likely to attract attacker interest.

    • cve.references

      Extracting reference sources -> Certain sources such as GitHub, vuldb, exploit-db might be strong signals of active discussion.

  • Dangerous CWE types

    • cwe_list

      Certain CWEs are more prone to exploitation. As our previous analysis showed, specific vulnerability classes (like XSS or SQL Injection) appear far more frequently than others. We also know that these two CWEs are historically the most exploited weakness types. These structural weaknesses are often easier to automate and exploit at scale, making them strong predictors of future weaponization.

  • Product Vendors

    • Extracted from vulnerable_cpes

      Major vendors like Microsoft and Cisco are prime targets for hackers because their widespread use means a single exploit can hit thousands of victims, making their vulnerabilities far more likely to be attacked than those in targeted products.

  • Publication Timing

    • cve.published & cve.lastModified

      Newly published CVEs with rapid modification may indicate some growing awarness

  • Percentile

    • percentile

      Percentile encodes relative exploit likelihood in the global distribution. A CVE with low EPSS but a percentile close to 0.1 might already grow up.

  • Base Severity & Impact

    • cvss_baseSeverity & cvss_confidentialityImpact & cvss_integrityImpact & cvss_availabilityImpact

      These aspects reflect to potential impact but not the likelihood of exploitation. However, when combined with network attack vector and low attack complexity, they may indicate easier exploitation paths.

Less useful predictors:¶

  • cvss_baseScore & cvss_version

    CVSS measures impact, not exploit likelihood. High CVSS not imply future EPSS growth

EPSS Trend Analysis¶

To replicate this analysis and start the visualization application, run the provided Python script in your terminal using the following command:

streamlit run epss_tracker.py

The application collected daily probability scores from October 1, 2025 to present. The objective was to determine if risk scores remained stable or exhibited "velocity" (rapid growth).

Figure 1: Analysis of EPSS scores over a 2-month period.

The visual data confirms that risk is not static. While the majority of vulnerabilities remained flat, specific outliers demonstrated clear upward trends:

  • 🔴 CVE-2025-11031 (Red Line): This had the biggest change. It started low (0.05%) and tripled at 0.17%.
  • 🟣 CVE-2025-9789 (Purple Line): Doubled in score between October and November before staying flat again.

Takeaways¶

1. The "Step Function" of Risk

The trend lines do not rise smoothly; they jump in discrete steps. This suggests the score reacts to specific trigger events, such as a hacker attempting an exploit or the publication of new threat intelligence online.

2. Relative Growth vs. Absolute Score

Although the absolute probabilities remain low (<1%), there is some relative growth. The Red line grew by roughly 300% in two months. In a risk-based approach, this high velocity is an early warning sign that the vulnerability is transitioning into an active threat.

Monitoring the rate of change (trend) is just as critical as analyzing the static score itself.
